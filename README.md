# Очередной лототрон

Адаптивное приложение для ведущего офлайн-розыгрыша. TypeScript, HTML, CSS, Vite и `vite-plugin-pwa`; без сервера и UI-фреймворков.

## Запуск

Нужен Node.js 22.12+ (проверено на Node.js 24) и npm.

**Быстрый запуск на Windows:** дважды нажмите `start-local.cmd` или выполните `./start-local.cmd` из терминала. Скрипт установит зависимости, если они отсутствуют, соберёт приложение с поддержкой офлайн и запустит его. После запуска в строке `Local` появится ссылка **http://localhost:4173/**. Окно нужно оставить открытым; остановка — `Ctrl+C`.

Порт фиксированный, поскольку сохранённый розыгрыш привязан к адресу сайта, включая порт. Если 4173 занят, закройте ранее запущенный сервер и повторите запуск. Первоначальная установка зависимостей требует интернета; последующие запуски с установленными зависимостями работают без него.

Для разработки вручную:

```sh
npm ci
npm run dev
```

Vite покажет адрес приложения. Service Worker включён только в production-сборке. Для проверки PWA:

```sh
npm run build
npm run preview
```

Откройте адрес localhost, напечатанный Vite. HTTP по LAN-адресу компьютера не является безопасным контекстом: для тестов на телефоне используйте HTTPS-хостинг.

## Docker

Установите и запустите Docker Desktop (Linux containers) или Docker Engine с Compose на Linux. Node.js на хосте для этого не нужен.

```sh
docker compose up -d --build
docker compose ps
```

Откройте http://localhost:4173/. Порт совпадает с локальным запуском: данные браузера привязаны к адресу, включая порт. Если порт занят, сначала остановите локальный preview.

```sh
docker compose logs app
docker compose down
```

Сборка использует Node.js 24 и `npm ci` с lock-файлом. В итоговом контейнере остаются только Nginx и статические файлы; Nginx работает без root на порту 8080. Файловая система контейнера доступна только для чтения, временные файлы находятся в `/tmp`. Проверка здоровья: `/healthz`.

Для хостинга контейнера соберите `docker build -t qp-generator .` и направьте HTTPS-прокси провайдера на порт 8080. Локальный Compose публикует порт только на loopback; размещение на сервере и подключение домена настраиваются отдельно под выбранный хостинг. Данные розыгрыша хранятся в браузере, Docker volume не нужен.

Для браузерной проверки запущенного контейнера в PowerShell:

```powershell
$env:E2E_BASE_URL = 'http://127.0.0.1:4173'
npm run test:e2e
Remove-Item Env:E2E_BASE_URL
```

Этот режим проверяет указанный сервер без запуска Vite preview.

## Сервер с общим HTTPS-шлюзом

Для отдельного контейнера за существующим Docker-шлюзом укажите его сеть в локальном `.env` сервера: `GATEWAY_NETWORK=server149_qp_edge`. Файл `.env` исключён из Git.

```sh
docker compose -p qp-generator -f compose.yaml -f compose.production.yaml up -d --build --wait
```

Контейнер получает имя `qp-generator` в сети шлюза. Пример маршрута Caddy:

```caddyfile
generator.bibun.app {
    encode zstd gzip
    reverse_proxy qp-generator:8080
}
```

DNS поддомена должен указывать на сервер. Caddy выпускает и продлевает HTTPS-сертификат; его хранилище сертификатов должно оставаться в постоянном volume. Конфигурация общего шлюза управляется из проекта server149 (`/opt/server149`), отдельно от приложений. Изменять Caddy при обновлении генератора не требуется. На этом VPS команды Compose можно выполнять через `/opt/server149/scripts/generator-compose.sh`. Генератор подключён только к своей сети шлюза и не имеет доступа к сети PostgreSQL chush.

Обновление приложения: `git pull --ff-only`, затем повторный запуск команды Compose выше. Для остановки только генератора используйте `docker compose -p qp-generator -f compose.yaml -f compose.production.yaml down`. Не удаляйте внешнюю сеть шлюза и volumes других проектов.

## Публикация

Загрузите содержимое `dist/` на статический HTTPS-хостинг. Поддерживается размещение в подкаталоге; открывайте его адрес с завершающим `/`. Серверная база, секреты и переменные окружения не нужны. Не удаляйте ресурсы старой версии во время атомарного переключения релиза, если хостинг позволяет их сохранить.

Для `index.html`, `sw.js` и `manifest.webmanifest` используйте `Cache-Control: no-cache`; для `assets/` с хешами в именах — `public, max-age=31536000, immutable`. Не перенаправляйте запросы отсутствующих JS-файлов на HTML. Весь сайт должен быть доступен без авторизации; MIME-типы JS, CSS и манифеста должны быть корректными.

Обновление скачивается в фоне и остаётся ожидающим. Приложение не вызывает `skipWaiting` и не перезагружает страницу. Для применения обновления закройте все вкладки и установленное приложение, затем откройте снова. Состояние IndexedDB сохраняется. При будущих изменениях схемы нужны совместимые миграции, без удаления базы.

## Подготовка ведущего

1. Откройте приложение с интернетом. Дождитесь зелёного статуса «Готов к работе».
2. При желании установите приложение: на iPhone через «Поделиться» → «На экран Домой», на Android через меню установки браузера. На компьютере установка доступна в поддерживающих браузерах.
3. В той установке, которой будете пользоваться на мероприятии, отключите сеть, закройте и снова откройте приложение. Проведите пробный розыгрыш и проверьте восстановление после закрытия.
4. Сбросьте пробный розыгрыш, введите реальное число участников и начинайте.

Данные принадлежат браузеру/установке на этом устройстве. Очистка данных сайта, приватный режим, удаление приложения и освобождение хранилища браузером могут удалить данные. Облачной копии нет. Статус готовности подтверждает установку офлайн-ресурсов, но не обещает вечное хранение браузером.

## Как устроено

- Допустимы целые числа от 1 до `Number.MAX_SAFE_INTEGER` (9 007 199 254 740 991). Это предел точного представления, а не продуктовый максимум. Экспоненциальная запись и дроби отклоняются.
- `crypto.getRandomValues` даёт 53 случайных бита; rejection sampling с BigInt устраняет смещение преобразования в диапазон.
- Ленивый Fisher–Yates хранит перестановки в IndexedDB. Начало не требует массива из N элементов, один выбор читает и меняет постоянное число записей. Хранилище растёт по числу выполненных выборов, до доступной квоты устройства.
- Метаданные, перестановки и история изменяются одной транзакцией. Результат показывается только после `transaction.oncomplete`; анимация запускается после сохранения.
- История читается по 50 записей. В DOM не накапливается весь список.
- Web Locks разрешает управление только одной вкладке. Следующая автоматически получает управление после закрытия первой. Браузер без Web Locks получает понятную ошибку вместо небезопасного параллельного управления.
- Анимация включена по умолчанию; системный `prefers-reduced-motion` подавляет перебор независимо от сохранённого переключателя.
- Все необходимые ресурсы локальные. Офлайн-статус появляется после успешной установки Service Worker и предварительного кеша.

## Проверки

```sh
npm test
npx playwright install chromium webkit
npm run build
npm run test:e2e
```

Vitest проверяет валидацию, отбрасывание смещённого хвоста, равновероятность всех последовательностей для трёх участников, отсутствие повторов до N=10000, большие N, восстановление перестановок, пагинацию и атомарный откат при ошибке.

Playwright запускает сценарии в настольном Chromium, мобильной эмуляции Pixel 7 (Chromium) и iPhone 13 (WebKit). Проверяются сброс и отмена, восстановление, блокировка повторных нажатий, конфликт вкладок, ошибки записи, длинная история, уменьшение движения и вместимость многозначных номеров. Офлайн-проверка выполняется отдельно в Chromium; соответствующий WebKit-сценарий явно пропущен.

Реальные Android/iPhone и нативные браузеры macOS пока не проверены. Эмуляция WebKit не заменяет Safari на iPhone. Перед мероприятием требуется проверка установки, автономного запуска и перезапуска устройства на реальном телефоне.

Результаты проверки 22.09.2026: production-сборка успешна; 24 теста Vitest прошли; 20 сценариев основного набора Playwright прошли, один офлайн-сценарий WebKit пропущен. Дополнительно прошёл отдельный Chromium-тест обновления Service Worker: новая версия ждёт, страница не перезагружается, розыгрыш продолжается и восстанавливается после закрытия. Проверка npm после обновления зависимостей: 0 известных уязвимостей.

`scripts/screenshots.mjs` создаёт локальные снимки интерфейса в `screenshots/` с работающего preview на `http://localhost:4174`. Снимки, кеши, логи, результаты тестов и сборка исключены из Git. Docker-контекст включает только файлы, необходимые для сборки и запуска. Исходники, тесты, техническое задание и лицензия шрифта сохранены.
